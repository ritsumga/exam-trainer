# 問題妥当性レビュー基準

## 1. 構造と整合性

- `id`、`exam`、`domain`、`type`、`difficulty`、`answers`、`Question`、`Explanation`が存在する。
- `exam`と`domain`が対応するExam Pack定義に存在する。
- `type`が`single`、`multiple`、`input`のいずれかである。
- `single`の正解は1件で、選択式の正解はすべて`choices`に存在する。
- 問題IDが既存問題と重複せず、難易度が1〜5である。
- 製品同梱候補には非空の`sources`と`verifiedAt`があり、人の承認後に限り`status: approved`である。
- 工程1以降に確定したスキーマやValidator規則がある場合は、その規則を優先する。

## 2. 技術的正確性

- 正解と解説が、確認可能な公式資料または一次資料と一致する。
- バージョン、前提条件、例外条件が正解を変える場合は問題文に明示されている。
- 時点により変化する内容には、出典と`verifiedAt`が対応している。
- 出典が主張を直接裏付けず推論が必要な場合は、推論であることをレビュー結果に明記する。

## 3. 設問品質

- 問題文だけから問う内容と解答条件を理解できる。
- 意図した正解が一意で、複数の合理的な解釈が生じない。
- 否定表現、二重否定、不要なひっかけ、正解を推測できる表記差がない。
- `multiple`では選択数または全選択方式が明確である。
- `input`の各正解候補へUnicode NFC正規化、改行コードのLF統一、前後のUnicode空白除去を適用した結果が重複していない。
- `input`では大文字小文字、全角半角、内部空白を区別しても正解が一意である。許容すべき表記揺れは別の`answers`として明示されている。

## 4. 選択肢と解説

- 誤答選択肢はもっともらしいが、問題の前提では明確に誤りである。
- 選択肢の粒度、文法、長さが不自然に正解を示唆しない。
- 解説は正解の理由を説明し、選択式では各誤答が誤りである理由も説明する。
- 解説が問題文の単なる言い換えになっていない。

## 5. 試験との対応

- 問題が対象試験と分野の学習目的に対応している。
- 特定Exam Packの知識を共通UIや共通エンジンの仕様として要求していない。
- 難易度は要件定義6.6の5段階基準に照らして妥当である。

## 6. 出典、独自性、公開条件

- 公開候補には、正解と主要な解説を直接検証できる公式資料または一次資料のHTTPS URLが`sources`に1件以上あり、全資料との最終照合日が`verifiedAt`へ`YYYY-MM-DD`で記録されている。
- 一次資料が存在せず二次資料を使う場合は、その理由、資料の信頼性、直接確認できない主張をレビュー結果へ記録する。
- 参照資料の表現をそのまま問題文や解説へ移さず、事実に基づく独自の文章になっている。
- 実在試験の記憶問題、試験ダンプ、第三者問題集の転記や軽微な言い換え、出所不明の問題に依存していない。
- AI生成か人作成かにかかわらず、Validator成功、内容レビューの`承認候補`、人による問題単位または明示した集合単位の承認がそろうまで正式問題として扱わない。
- AIまたは自動処理は`status`を`approved`へ変更しない。レビュー時点で人の承認前なら、内容が妥当でも現在の状態を維持し、人の最終判断事項へ記載する。
