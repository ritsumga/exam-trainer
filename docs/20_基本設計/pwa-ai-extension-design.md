# Exam Trainer PWA・AI拡張基本設計

## 1. 目的

本書は、v1のオフライン範囲、Service Workerの更新方式、GitHub Pages配布、将来のAI Provider境界と承認状態を定める。

## 2. オフライン利用範囲

初回のオンライン読込とService Worker有効化後、次をオフラインで利用可能にする。

- 試験選択と試験ホーム
- 通常演習、採点、解説、履歴保存
- 未回答、誤答、お気に入り、分野別、ランダム、弱点演習
- 模擬試験の開始、中断保存、再開、提出、結果表示
- 成績表示
- IndexedDB内データのバックアップ出力と復元

外部の出典URLを開く操作はオフライン保証の対象外とし、リンク自体は表示する。v1の主要機能は外部APIを呼び出さない。

## 3. キャッシュ設計

| 対象 | 方針 |
| --- | --- |
| HTML、JavaScript、CSS | Viteビルド成果物を事前キャッシュする |
| Web App Manifest、アイコン | インストールに必要な静的資産として事前キャッシュする |
| 生成済みPackカタログ | アプリコードと同じビルド版で事前キャッシュする |
| 製品Packデータ | 主要学習機能のオフライン利用に必要な静的資産として事前キャッシュする |
| 出典の外部ページ | キャッシュ管理対象外とする |
| 試験fixture | 製品ビルドとキャッシュ対象から除外する |
| 学習履歴 | Cache StorageではなくIndexedDBへ保存する |

コード、カタログ、Packを同じビルド成果物として版管理し、異なる版を任意に組み合わせない。生成ファイルには内容ハッシュを利用し、旧キャッシュは新版が有効化された後に整理する。具体的なWorkbox設定は工程3で確定する。

## 4. Service Worker更新

1. アプリ起動時とオンライン復帰時にService Workerの更新を確認する。
2. 新版が待機状態になったら、非遮断通知で「更新」と「後で」を提示する。
3. 「後で」を選んだ場合は現在版を継続し、次回起動または次の更新確認時に再通知する。
4. 「更新」を選んだ場合、未完了模試の最新操作が保存済みであることを確認する。
5. 保存済みなら待機中Service Workerを有効化して再読込する。未保存または保存失敗なら更新を中止し、理由を通知する。
6. 再読込後に未完了模試があれば、絶対期限を評価して再開または期限切れ自動提出へ進む。

即時自動再読込は行わない。複数タブでの更新通知と有効化調停は工程3で詳細化する。

## 5. PWA状態と障害時動作

- オフライン準備完了を通知し、初回キャッシュ前のオフライン利用を保証しない。
- オフライン中の更新確認失敗は学習を妨げず、オンライン復帰後に再確認する。
- Service Worker登録失敗時は通常のオンラインWebアプリとして起動し、オフライン利用不可を通知する。
- Packまたはアプリ資産が欠けている場合は古いデータへ黙ってフォールバックせず、再接続と再読込を案内する。
- IndexedDBの保存失敗はキャッシュ更新と別の障害として扱う。

## 6. GitHub Pages配布

- Viteの`base`は`/exam-trainer/`とする。
- ルートはhash部分へ置き、Pagesサーバーには常に配布ルートの静的資産を要求する。
- Pages公開は承認済み`main`をGitHub Actionsでビルドした成果物だけを対象にする。
- APIキー、アクセストークン、利用者データをビルド成果物へ含めない。
- push、可視性変更、Pages有効化、初回デプロイは工程承認とは別の人の明示承認を必要とする。

## 7. AI拡張境界

将来のAI機能は機能サービスから`AIProvider`を介して呼び出す。ドメインモデル、Packビルド、UIは特定ProviderのSDK、通信方式、モデル名、認証方式を参照しない。

`AIProvider`の概念操作は次とする。

- 資料と生成条件から問題候補を返す。
- 問題候補と評価条件からレビュー結果を返す。
- 利用不能、入力不正、生成失敗、レビュー失敗を区別して返す。

具体的なTypeScriptシグネチャとエラー型は工程3以降で確定する。v1ではインターフェース設計だけを残し、実装、設定画面、通信、APIキー保存を行わない。

## 8. 問題状態と承認境界

```text
資料
  ↓
AIまたは人による生成
  ↓
draft
  ↓ AIまたは人によるレビュー
reviewed / rejected
  ↓ Validator + 問題妥当性レビュー + 人の明示承認
approved
  ↓
製品Packへ配置して再ビルド
```

- `AIProvider`は`approved`を返したり設定したりできない。
- AI出力は製品Pack外の下書きとして扱い、製品ビルドの入力へ自動接続しない。
- Validator成功やAIレビューは、人の公開承認を代替しない。
- 製品Packに配置できるのは、出典、確認日、承認状態を満たす独自問題だけとする。

## 9. 費用・セキュリティ

- v1にバックエンド、ログイン、クラウドDB、課金APIを追加しない。
- AI SDK、Provider実装、APIキー、外部モデルダウンロードをv1の依存へ含めない。
- 将来Providerを追加しても、利用者が明示設定しない限り外部へ問題、履歴、設定を送信しない。
- ローカルProviderを含む将来実装は、送信対象と保存場所をProvider単位で明示する。
