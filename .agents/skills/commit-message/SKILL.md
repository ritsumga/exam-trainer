# コミットメッセージ作成

Exam Trainerの変更内容を根拠に、`docs/00_開発管理/development-workflow.md`へ適合するコミットメッセージ案を作成する。

## 手順

1. `git status --short`、対象差分、現在のブランチを確認する。ユーザーが対象を限定した場合は、その範囲だけを扱う。
2. 差分の主目的を1つに要約する。独立した目的が混在する場合は、無理に1件へまとめず分割案を示す。
3. `docs:`、`feat:`、`fix:`、`test:`、`build:`、`ci:`、`chore:`から差分の主目的に合う種別を選ぶ。
4. 件名は`<種別>: <日本語の要約>`とし、命令形に限定せず、変更結果が分かる簡潔な表現にする。
5. 承認済み要件へ影響する場合は、本文へ要件IDと影響を記載する。工程成果物の場合は対象工程も本文へ記載する。
6. 検証結果がコミットの理解に必要な場合だけ、本文へ実行コマンドと結果を記載する。

## 出力

- 第一候補をコードブロックで提示する。
- 分割が必要な場合は、コミットごとに対象ファイルとメッセージ案を提示する。
- 根拠にした差分が未確認、または変更目的を一意に判断できない場合は、その点を明示する。

## 制約

- 差分にない変更、要件ID、検証結果を推測して記載しない。
- 工程承認、外部操作の承認、問題の公開承認をコミットメッセージで代替しない。
- ユーザーから明示的に依頼されない限り、`git add`、`git commit`、タグ作成、pushを実行しない。
